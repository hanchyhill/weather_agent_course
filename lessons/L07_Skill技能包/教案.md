# L7 Skill：把预报经验做成可复用的“技能包”

| 项目 | 内容 |
|---|---|
| 时长 | 3 小时 |
| 对应计划 | `plan/03-能力与综合篇.md` L7 |
| 本讲文件 | `01_用Skill沉淀经验.ipynb`（**需真实模型**）、`99_假模型剧本.ipynb`（没有 Key 时看流程用） |

## 教学目标

1. 理解 Skill 与系统提示词的区别：按需加载、按专题维护。
2. 能独立写一个 `SKILL.md`，并让它在该用时被用上、不该用时不被用上。
3. 从本讲起改用 deepagents 的 `create_deep_agent`。

## 讲解要点（40 分钟）

1. 为什么需要 Skill：所有规范都塞进系统提示词，提示词会越来越长、互相干扰，也不便于不同人维护。
2. Skill 的结构：
   - 名片（`name`、`description`）：智能体只看名片决定是否加载。description 要写清“做什么 + 什么时候用”。
   - 正文：步骤、规范、参考表。用到时才读。
3. 适合做成 Skill 的预报经验：描述规范、等级标准、地理分区、会商稿章节规范、某类天气的关注要点。
4. 同样的 SKILL.md 格式，Claude Code 也能用（`huishang_demo/.claude/skills/` 下的 `slide`、`skill-creator`）。
5. 代码上的变化：`create_agent` → `create_deep_agent`，多了 `skills=` 和 `backend=`。`virtual_mode=True` 把文件访问限制在课程包内。

## 演示（20 分钟）

- notebook 第 2 节：问风速等级，在轨迹里指出智能体读了哪个文件。
- 点出 L3 找茬练习发现的“7.2”错误已在这个 Skill 里改正。

## 实操（90 分钟）

| 练习 | 内容 | 检查点 |
|---|---|---|
| 1（20 分钟） | 运行 notebook 第 2、3 节（真实模型） | 风速题读了 typhoon-grade；“现在几点”没有读任何 Skill |
| 2（40 分钟） | 写自己的 Skill（notebook 第 4 节） | 名片写清适用场景；正文是步骤不是散文 |
| 3（30 分钟） | 对比实验：最高气温描述，加/不加 tmax-description | 按 L2 的 9 项指标打分，加 Skill 的得分更高 |

练习 2 给 Claude Code 的需求示例：

> 我口述一段回南天的判断经验，你帮我整理成 `skills/huinantian/SKILL.md`。开头 name 用 huinantian，description 写清“什么时候用”。正文分“判断条件”“关注要点”“常见误判”三节，用列表写。整理完给我看，先不要改别的文件。

## FAKE 模式说明

正式讲义 `01_用Skill沉淀经验.ipynb` 里**不写剧本**，Skill 会不会被读到完全由真实模型判断；源文件头部标了 `<!-- course-meta: real-llm -->`，`build_notebooks.py --execute` 只转换、跳过执行。

没有 Key 时看 `99_假模型剧本.ipynb`：那一份用 `llm.agent_model(...)` 写死“先读 SKILL.md 再回答”，第一格强制 `COURSE_FAKE_LLM=1`。Skill 列表注入和 `read_file` 执行是真的，只有“想不想读”是剧本；description 写得好不好，必须用真实模型才试得出来。

## 讲师备注

- deepagents 0.7.23 会把 Skill 列表（名字 + 描述 + 文件路径）写进系统提示词，智能体用 `read_file` 读全文。Skill 列表能正确注入已用假模型验证过，见 `99_假模型剧本.ipynb`。
- 学员写的 Skill 放在 `skills/` 下即可被自动发现，不用改代码。
