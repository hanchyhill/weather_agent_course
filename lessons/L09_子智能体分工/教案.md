## 教学目标

1. 理解为什么要分工，以及什么时候不该分工。
2. 会用字典声明子智能体，写好 `description`。
3. 能把 L8 的台风智能体并入中枢，有台风时调用、无台风时简写。

## 讲解要点（40 分钟）

1. 类比会商：首席分派，各组分析，首席汇总定调。
2. 子智能体的字典写法：`name`、`description`、`system_prompt`、`tools`、（可选）`model`。参照 `huishang_demo/src/new_weather_situation_agent.py` 的 `build_subagents`。
3. `description` 决定中枢什么时候派活，重要性和工具 docstring 一样。
4. 上下文隔离：子智能体不共享对话，只交回结论。中枢的上下文因此保持干净，但也意味着交回的格式要约定好。
5. 不该分工的情形：任务简单、步骤少。分工会增加调用次数和成本。
6. 本讲复用 L8 的台风智能体：`ta.SYSTEM_PROMPT` 和 `ta.TOOLS` 直接作为台风组的配置。

## 演示（20 分钟）

用真实模型运行 notebook 第 2 节，讲轨迹：中枢的 `task` 调用 → 子智能体返回一句结论 → 中枢汇总。强调中枢看不到子智能体内部调用了哪些工具。没有 Key 时可以先用 `99_假模型剧本.ipynb` 讲结构，配好 Key 再换成真实运行。

## 实操（90 分钟）

| 练习 | 内容 | 检查点 |
|---|---|---|
| 1（20 分钟） | 小组设计分工表（notebook 第 1 节表格） | 每组写清职责、工具、交回格式 |
| 2（30 分钟） | 真实模型下运行中枢，分别用有台风、无台风的时间 | 台风组被调用；无台风时会商意见简写 |
| 3（20 分钟） | 改含糊台风组的 `description` | 记录中枢是否还能正确派活 |
| 4（20 分钟） | 让 Claude Code 新增一个子智能体（如“降水组”） | 中枢在问到降水时调用它 |

## 复盘（30 分钟）

- 练习 3 的结果：description 含糊时出了什么问题？
- 讨论：子智能体交回的结论有冲突（例如实况组说粤西高温，台风组说粤西有强降雨），中枢应该怎么写？
- 引出 L10：发布前要有人把关，报告质量要有评分标准。

## FAKE 模式说明

正式讲义 `01_会商中枢_T9.ipynb` 里**不写剧本**，全部用真实模型：只有真模型才会自己判断该派给谁、派不派，练习 3（把 `description` 改含糊，看中枢还派不派）才有意义。它靠源文件头部的 `<!-- course-meta: real-llm -->` 标记，`build_notebooks.py --execute` 只会转换、跳过执行。

没有 Key 时看 `99_假模型剧本.ipynb`：那一份给中枢和两个子智能体各写一份剧本（`llm.agent_model(...)`，通过 `hub.build_hub(main, subs)` 传入），并在第一格强制 `COURSE_FAKE_LLM=1`。要跟学员强调：派活的顺序、派给谁都是写死的，只能看上下文隔离的结构，看不出 `description` 写得好不好。
