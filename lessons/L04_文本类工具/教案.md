# L4 第一个工具：文本类气象接口

| 项目 | 内容 |
|---|---|
| 时长 | 3 小时 |
| 对应计划 | `plan/02-工具篇.md` L4，`plan/05-台风专线渐进式案例.md` T0、T1 |
| 本讲文件 | `01_读懂台风数据_T0.ipynb`、`02_按世界时查询_T1.ipynb`（源文件 `.nb.py`，**需真实模型**）、`99_假模型剧本.ipynb`（没有 Key 时看流程用）、`03_备选_陆地大风工具.py`、`test_windland.py` |
| 数据 | `data/typhoon_api/`：huishang_demo 真实运行日志中的台风接口返回 |

## 教学目标

1. 理解工具的三要素：名字、说明（docstring）、参数。
2. 能读懂台风接口返回的 JSON，说出关键字段含义。
3. 亲眼看到“让模型自己换算时区”会出错，为 L5 做铺垫。

## 讲解要点（40 分钟）

1. 工具分三类，从简单到复杂：
   - 纯计算，不联网：预报时效表（L0 已见过）
   - 一次请求、直接返回：预警统计 `alarm`、陆地大风 `windLand`（agent_dev）、台风查询 `getyphdata`（huishang_demo）
   - 调用后还要交给视觉模型：L6 讲
2. 返回文本还是 JSON：给模型读的用中文文本；要给下一个工具接着用的（比如 tsid）保留 JSON。
3. docstring 是写给模型的使用说明，要写清：什么时候用、参数格式、返回什么、调用顺序。
4. 台风数据的两个时间：资料时次（`datetime`）和预报发布时间（`预报时间`），不是一回事。

## 讲师备注

- 离线库只收录了几个真实时次（见 `data/typhoon_api/getyphdata.json` 的 `_说明`）。未收录的时次按“无台风”返回，正好让 T1 的换算错误表现为“查不到台风”。
- 陆地大风的离线数据是教学构造的，字段格式参照 agent_dev 的 `windLand` 读取逻辑，不是真实接口返回。
- **内网取数地址不在讲义里明文出现**：T1 的工具通过 `weather_tools.typhoon.data_endpoint()` 取地址（包里以编码形式保存），报错信息里也不再回显地址，避免被学员随手复制滥用。讲师若要把接口指向自己的代理，在 `.env` 填 `TYPHOON_API_URL`（模板中用 `{datetime_bj}` 占位北京时），留空则用内置地址。

## 常见问题

| 现象 | 处理 |
|---|---|
| 跑正式 notebook 报 `.env 中没有填写 MAIN_API_KEY` | 这一讲要用真实模型，没配 Key 先跑 `99_假模型剧本.ipynb` |
| T1 的工具返回“无法连接到台风数据服务” | 台风接口在内网，校外只能看到这句错误说明（讲义和报错里都不显示接口地址）；换算是否正确仍可从工具参数判断 |

## FAKE 模式说明

正式讲义 `02_按世界时查询_T1.ipynb` 里**不写剧本**，全部用真实模型，避免学员把预设台词当成模型自己说的话。它靠源文件头部的 `<!-- course-meta: real-llm -->` 标记，`build_notebooks.py --execute` 只会转换、跳过执行；`01_读懂台风数据_T0.ipynb` 同样标了该标记（内容不调模型，标记是为了统一跳过执行）。

没有 Key 时看 `99_假模型剧本.ipynb`：那一份用 `llm.agent_model(...)` 写死剧本（故意让模型忘了换算），并在第一格强制 `COURSE_FAKE_LLM=1`，打开就能跑。要跟学员强调：剧本里 100% 会算错，真实换算正确率必须用真实模型多问几次统计，练习 T1 才有意义。
