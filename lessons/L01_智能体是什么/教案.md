# L1 智能体是什么：从聊天到 Agent

| 项目 | 内容 |
|---|---|
| 时长 | 3 小时（讲解 40 分钟，演示 20 分钟，实操 90 分钟，复盘 30 分钟） |
| 对应计划 | `plan/01-入门篇.md` L1 |
| 本讲文件 | `01_第一个智能体.ipynb`（**需真实模型**）；`99_假模型剧本.ipynb`（没有 Key 时看流程用） |
| 参考课件 | `pptx/ch01-agent-harness.pptx`、`pptx/ch02-quickstart.pptx` |

## 教学目标

1. 说清 LLM、提示词、工具、智能体循环四者的关系。
2. 能读懂一次运行的轨迹：哪一步是模型决定、哪一步是程序执行。
3. 体会工具说明（docstring）对模型行为的影响。

## 讲解要点（40 分钟）

用预报员熟悉的类比：

| 概念 | 类比 |
|---|---|
| LLM | 刚上岗的新预报员：知识面广，但没看过今天的资料 |
| 工具 | 业务系统里的各类产品和查询接口 |
| 提示词 | 岗位手册：职责、规范、写稿要求 |
| 智能体循环 | 看资料 → 分析 → 发现缺什么再去查 → 写结论 |

板书智能体循环：

```
用户提问 → 模型思考 →（需要资料？）→ 调用工具 → 拿到结果 → 模型再思考 → … → 最终回答
```

强调两点：

- 调不调工具、调哪个、传什么参数，是模型自己决定的。程序只负责执行。
- 模型只能看到工具的名字、说明和参数。说明写不清，模型就不会用或用错。

最后简单介绍两个框架：本讲用 LangChain 的 `create_agent`（最简单的循环）；L7 起换成 deepagents 的 `create_deep_agent`（多了任务规划、文件系统、技能包、子智能体）。第 5、6 节会现场对比两者：同一套工具，`create_agent` 只绑 2 个，`create_deep_agent` 绑 10 个（多出 `ls`、`read_file`、`write_file`、`edit_file`、`delete`、`glob`、`grep`、`task`）。

## 演示（20 分钟）

讲师运行 notebook 第 1、2 节：

1. 只有模型时问“现在几点”，模型答不上来。
2. 加上 `get_beijing_time` 工具再问，展示运行轨迹，逐条解释 [1]～[4]。

如果讲台电脑配了 LangSmith，同时打开 LangSmith 的轨迹页面对照。

## 实操（90 分钟）

| 练习 | 内容 | 检查点 |
|---|---|---|
| 1 | 自己运行 notebook 第 1～2 节 | 能指出轨迹里哪一条是“模型决定调用工具” |
| 2 | 第 3 节：把 docstring 改成“时间”，真实模型下问 5 次；工具已改为返回世界时 | 记录调用了几次，对比原 docstring 的结果；看它是否把世界时当北京时报出来 |
| 3 | 第 4 节：区县查询工具 | 问“连州属于哪个市”，能得到“清远”。再问“乐昌和南雄”，观察模型是否调用两次 |
| 4（进阶） | 改造 `find_city_of_county`，使其一次支持查询多个区县 | 问“连州、乐昌、南雄都属于哪个市”，答案和 CSV 一致 |
| 5 | 第 5~6 节：同一个问题“你能使用哪些工具？”分别问 `create_agent` 和 `create_deep_agent` | 能说出 deep agent 多出哪些内置工具；能解释探针数出的 2 个 vs 10 个 |

**工作目录与工具箱扩展（结合第 5～7 节）：**配置 `LocalShellBackend` 工作目录，分别询问目录内容、Python 版本和系统信息；检查工具清单。再用同一道多步骤问题比较两个智能体，理解 `write_todos` 需要显式加入中间件，简单问题不一定触发规划。最后询问 Codex、Claude Code、WorkBuddy 或 VS Code Copilot 的工具能力，截图比较。工作目录只选择学员有权限使用的范围。

## 复盘（30 分钟）

- 练习 2 的统计：docstring 含糊时，全班平均调用率是多少？
- 讨论：如果一个工具的说明写的是“查询台风”，模型能知道该传北京时还是世界时吗？（引出 L4、L5）

## 验收

- [ ] 能在轨迹中指出模型决策和工具执行
- [ ] 能解释 docstring 写不清时模型为什么不调用工具
- [ ] 区县查询工具在智能体里能正确使用
- [ ] 能说清 `create_agent` 和 `create_deep_agent` 的工具箱差异，以及 `write_todos` 需要显式加 `TodoListMiddleware`

## 常见问题

| 现象 | 处理 |
|---|---|
| 工具返回的时间不是电脑时间 | `.env` 中 `COURSE_NOW` 固定了课程时间（后面几讲的离线数据需要）。留空即用电脑时钟，做 L4 前改回 `2026-08-11 08:30`。改完立即生效，不用重启 |
| `ImportError: cannot import name ...` | 内核里是旧模块。重启内核，从第一格重新运行 |
| 打印出一长串 `[{'type': 'text', ...}]` | 公共代码已处理（取 `.text`）。如果仍出现，说明内核是旧的，重启即可 |
| 跑 `01_第一个智能体.ipynb` 报 `.env 中没有填写 MAIN_API_KEY` | 这一讲必须用真实模型。没配 Key 就先跑 `99_假模型剧本.ipynb`，配好再回来 |

## FAKE 模式说明

正式讲义 `01_第一个智能体.ipynb` 里**不写剧本**，全部用真实模型，避免学员把预设台词当成模型自己说的话。它靠源文件头部的 `<!-- course-meta: real-llm -->` 标记，`build_notebooks.py --execute` 只会转换、跳过执行。

没有 Key 时看 `99_假模型剧本.ipynb`：那一份用 `llm.agent_model(...)` 写死剧本，并在第一格强制 `COURSE_FAKE_LLM=1`，打开就能跑。要跟学员强调：剧本是写死的，轨迹只能看结构，练习 2（docstring 影响）必须用真实模型才有意义。
