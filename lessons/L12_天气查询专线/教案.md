# L12 天气查询专线：日期如何影响工具调用

| 项目 | 内容 |
|---|---|
| 时长 | 3 小时，可独立开课或作为 L4～L5 的补充 |
| 前置 | L1 的工具调用；建议先学 L5 时间换算 |
| 离线练习 | `01_三个工具_W1_W3.ipynb`、`02_今天要查两个工具_W4.ipynb`、`03_北京时与世界时_W5.ipynb`、`weather_agent.py` |
| 真实接口练习 | `03_真实天气接口_W1_W3.ipynb`、`real_weather_tools.py` |
| 无 Key 演示 | `99_假模型剧本.ipynb`；台词与调用是预设的 |

## 教学目标

1. 根据昨天、明天和今天判断实况与预报的选择、起止时间及数据覆盖。
2. 比较提示词改进前后的工具调用，理解覆盖缺口、数据延迟和模型波动。
3. 在离线练习中比较模型心算时区与程序换算，并检查真实工具参数。
4. 区分离线模拟与真实服务的接口形式和时间。

## 准备

离线数据 `data/weather/` 是教学构造数据；01 的初始化单元格将课程时间设为北京时 2026-08-11 08:30。02、W5 的离线实验应核对当前 `COURSE_NOW` 是否仍为该时间。正式 notebook 需要 `MAIN_API_KEY`；真实接口 notebook 还需 `BASE_URL_WEATHER_API` 和可访问服务的网络，它使用电脑当前北京时。

离线 `geocode_place` 是课程模拟工具，处理唯一、重名和未找到；离线实况与预报使用经纬度和 UTC 时间。真实接口普通查询直接传地点名称和北京时，不要求先地理编码；预报起报及返回覆盖以实际服务为准。

## 教学流程（180 分钟）

| 时间 | 任务 | 检查点 |
|---|---|---|
| 25 分钟 | 预测昨天、明天、今天分别需要的资料；讲解地点、时间窗口、实况和预报 | 能解释跨过当前时间为何需区分两类数据 |
| 35 分钟 | 离线 W1～W3：运行 01，观察地名解析、历史、预报及“今天”的调用 | 重名不自行选择；核对 UTC 参数和空结果 |
| 30 分钟 | 离线 W4：运行 02 的提示词对比和 `check_calls` | 检查是否漏调、窗口是否正确；统计多次结果，不预设提升 |
| 30 分钟 | 离线 W5：运行 03，比较提示词换算和程序换算 | 自然日跨 UTC 日期；区分时区错误和工具选择错误 |
| 40 分钟 | 真实接口 notebook：昨天、明天、当前出行问题及改进后的今天 | 检查工具名、北京时参数、返回覆盖及失败信息 |
| 20 分钟 | 汇报与讨论 | 解释实况延迟、预报起报和时段缺口 |

真实接口 notebook 的基础示例当前问“现在出门需要防晒吗”，改进示例问“今天的天气如何”。这两个问题并非严格 A/B：时间范围和业务意图可能不同。若要检验提示词效果，学员应让两组使用同一个问题、工具和时间条件。防晒问题还需核实工具是否提供紫外线等依据，不能仅凭气温推断。

## 验收

- [ ] 根据调用轨迹说明昨天、明天、今天各自使用的数据及实际时段。
- [ ] 能区分离线 UTC 参数与真实接口的北京时约定，并说明实际数据覆盖。
- [ ] 能比较基础与改进提示词，记录差异和不确定性；不以模型回答代替工具调用证据。
- [ ] 能解释服务不可达、无数据、实况延迟和预报起报的影响。

## 讲师提示

假模型只演示固定轨迹，不能据此统计真实模型通过率；多次实验会增加模型调用和服务请求。离线数据只覆盖特定个例，不是真实观测。真实服务依赖网络与部署端数据，不应把空结果或模型推断当作事实。
