# L12 天气查询专线：从“昨天天气”到“北京时 / 世界时”

| 项目 | 内容 |
|---|---|
| 时长 | 3 小时（可独立开课，也可作为 L4～L5 的第二条案例线） |
| 前置 | 学过 L1（智能体循环）、L4（工具三要素）；学过 L5 更好（时区思路相同） |
| 本讲文件 | `01_三个工具_W1_W3.ipynb`、`02_今天要查两个工具_W4.ipynb`、`03_北京时与世界时_W5.ipynb`（源文件 `.nb.py`，**需真实模型**）；`99_假模型剧本.ipynb`（没有 Key 时看流程用）；`weather_agent.py`、`test_weather.py` |
| 代码 | `weather_tools/weather.py`（离线接口）、`weather_agent.py`（`@tool`、提示词、检查函数） |
| 数据 | `data/weather/`：地名库、实况站点、预报格点，**教学构造**，由 `tools/gen_weather_data.py` 生成 |

## 教学目标

1. 用户的三个问题（昨天、明天、今天）逐步驱动出三个工具：地名→经纬度、经纬度→实况历史、经纬度→预报。
2. 看到“今天”为什么难：时间段跨过“现在”，一个工具不够。
3. 学会用**提示词里的判断条件**优化工具选择（W4）。
4. 比较“改提示词”和“改工具”两种处理时区的办法，理解“必须百分之百对的事交给程序”（W5）。
5. 学会用 `check_calls` 检查“模型做了什么”，而不是只读回答。

## 渐进式阶梯

| 步骤 | 用户问题 | 新增 | 新增的难点 | 对应 agent_dev |
|---|---|---|---|---|
| W1 | （为后面铺路） | `geocode_place` | 重名、查不到要如实返回 | `userSpecialFromLocation` 的地点→坐标 |
| W2 | 广州天河区昨天的天气如何？ | `get_station_history` | 接口只认世界时；没数据要说明原因 | `getRealData`、`getWeatherDataReal` |
| W3 | 广州天河区明天的天气如何？ | `get_forecast` | 预报只覆盖起报时间之后 | `getForecastData`、`getWeatherDataFore` |
| （问题）| 广州天河区今天的天气如何？ | — | 只选一个工具，漏掉一半 | `weatherSpecial` 里 data_type 0/1/2 的判断 |
| W4 | 同上 | 提示词：跨“现在”必须两个都查 | 把判断条件写成规则 | `weatherSpecial` 的 实况/预报/实况+预报 |
| W5 | 三个问题 | 方案 A 提示词换算 / 方案 B `*_bj` 工具 | 北京时 vs 世界时，日期边界 | 台风专线 T1→T2 的同类问题 |

## 离线数据里埋的天气过程

| 北京时 | 过程 | 用来检验 |
|---|---|---|
| 昨天 8/10 15～17 时 | 雷阵雨，累计 19.9 mm | 窗口算错时降水、极值会偏 |
| 今天 8/11 17～18 时 | 阵雨，累计 8.5 mm（预报） | 只查预报时看不到早上；只查实况看不到傍晚雨 |
| 明天 8/12 14～18 时 | 中到大雨，累计 45.4 mm（预报） | 窗口 |

课程时间默认 2026-08-11 08:30（北京时），实况截止 08:00 北京时（UTC 00 时），预报从 09:00 北京时起。
**今天**的正确窗口：实况 UTC 8/10 16:00 ~ 8/11 00:00，预报 UTC 8/11 01:00 ~ 15:00，合起来恰好 24 小时、无缺口无重叠。

## 讲解要点（30 分钟）

1. 先把三个问题写在黑板上，问学员：每个问题需要哪些信息？（地点→坐标；时间段；过去还是未来）
2. 工具的返回要“带原因”：`no_data` 时告诉模型“最新实况到几点”“预报覆盖到几点”，模型才不会瞎编。
3. 查不到、重名是正常情况，写进 docstring（`ambiguous` 要问用户）。
4. 时间区间含两端：小时数据查“昨天”是 00～23 时，不是 00～24 时（会多取一条）。

## FAKE 模式说明

三份正式讲义 `01` / `02` / `03` 里**不写剧本**，全部用真实模型，避免学员把预设台词当成模型自己说的话。它们靠源文件头部的 `<!-- course-meta: real-llm -->` 标记，`build_notebooks.py --execute` 只会转换、跳过执行。

没有 Key 时看 `99_假模型剧本.ipynb`：那一份把三个 notebook 删掉的剧本按 W1～W5 集中复现（W3「今天」故意只查预报的错误演示、W4 一轮并行调两个工具、W5 方案 A / B 两种写法，以及「忘了减 8 小时」的错误窗口），第一格强制 `COURSE_FAKE_LLM=1`，打开就能跑。要跟学员强调：剧本是写死的，轨迹只能看结构，W4 / W5 的通过率必须用真实模型跑 A/B 单元才作数。


## 讲师备注

- 正式 notebook 里不再写剧本，全部用真实模型；剧本集中在 `99_假模型剧本.ipynb`：W3 的「今天」演示故意只查预报，W4 / W5 的剧本是「理想行为」，还有一格演「忘了减 8 小时」。真实模型下的通过率**没有实测过**，试讲时请先跑一遍 A/B 单元，按实际情况调整提示词和预期。
- `check_calls` 默认允许 1 小时误差；想更严格可传 `tol_hours=0`。
- 数据是构造的：天河、越秀、福田三个点，气温、降水按日变化加固定降水过程生成；不是真实观测。需要改天气过程时改 `tools/gen_weather_data.py` 的 `RAIN_BJ` 后重新生成，同时更新 `test_weather.py` 里的数值。
- 与 agent_dev 的差异：真实实现里天气描述由另一个 LLM 调用生成（`weatherFun`），这里让主智能体直接读 JSON 总结，少一层，便于专注讲工具和时间。
